# C2C 会话运营

“C2C 订单会话”按订单号、交易用户 UID 和状态筛选。查阅、回执和私有附件通过 Gateway 的敏感权限接口并留审计；后台不冒用交易用户，也不加入双方的用户 WebSocket 会话。页面支持最近历史、向前分页、精确 int64 标识、双方已读、订单进展和付款凭证查阅。自动更新由管理员显式开启，仅在页面可见并获得焦点时拉取有界增量，后台页不持续读取正文。

客服回复由服务器标记 `SUPPORT`，不会确认付款、放币或裁决申诉。服务器要求审批时复用已有审批对话框，请求服务固定为 `c2c`，审批绑定原路径、正文和请求号。发送响应未知时保留当前管理员与订单作用域的原请求，重试先查受审计回执；已提交则恢复原消息，UNKNOWN 才复用原正文重试。支持在交易双方尚未进入聊天时按订单建立固定双方会话，客服不会因此成为会话成员。

切换管理员会清理旧页面、审批对话框与私有图片 Blob URL。请求与下载绑定发起管理员身份，旧的刷新结果不能覆盖新登录，并发 401 共用一次刷新，刷新后的 401 不再无限循环。附件从带交易权限的接口读取，页面没有 R2 密钥或公开地址。

验收见 [validation/c2c-chat-20261020/evidence.json](validation/c2c-chat-20261020/evidence.json)。`npm run test` 使用工作区既有 Bun（1.3.14），12 项通过；lint 和 build 通过。本机真实 PostgreSQL、Gateway HTTP 与用户共享 WebSocket 联调覆盖 8 个场景，包括客服回复送达、丢失响应恢复、私有附件、身份切换及 1440/390 宽度。身份和 Core 为明确的测试夹具，文件系统模拟私有存储；真实 R2 与生产鉴权不在本轮浏览器验收范围，后端另有对应验证记录。管理端沿用现有深色界面。

复验先启动后端显式 `C2cBrowserQaTest`，再以 `VITE_GATEWAY_BASE_URL=http://127.0.0.1:17174` 和 `VITE_GATEWAY_PROXY_TARGET` 指向本机夹具启动 Vite。用户 Web 同时监听 17173 并连接该夹具，运行 `scripts/c2c-chat-browser.mjs`；Playwright 工具路径可由 `C2C_PLAYWRIGHT_MODULE`、`C2C_CHROMIUM_EXECUTABLE` 指定。本次仅验证和推送代码，没有发布服务器。
