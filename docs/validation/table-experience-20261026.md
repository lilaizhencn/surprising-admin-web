## 流程与数据含义

- 桌面键盘选择与单次详情请求、手机完整字段/操作卡片、大整数 ID 与金额显示。
- 延迟旧用户的会话与画像响应，再切换用户；旧响应不能覆盖新选择。
- 普通订单与条件单时间线分别使用准确 ID 和产品线；撤单先进入原有审批框，测试审批后仅发出一次被拦截的 503 请求。
- 手机费率选择和禁用入口、权限选择、导出详情及下载入口均检查；不执行真实业务写入。
- 横向滚动后的固定操作列、分页状态、长文本和深浅主题均检查。

## 复现

启动开发页，设置 `QA_PLAYWRIGHT_MODULE` 和可选的 `QA_CHROMIUM`，执行：

```bash
QA_SOAK_MS=60000 node scripts/table-experience-qa.mjs
```

`QA_URL` 默认 `http://127.0.0.1:5184`，`QA_OUTPUT` 控制输出位置。
本机最终验收使用已有的 `chromium_headless_shell-1243`；系统 Chrome 的补充运行使用 156.0.8078.47。
系统 Chrome 自动更新/崩溃报告进程可能占用测试管道，因此推荐使用隔离的测试浏览器。
