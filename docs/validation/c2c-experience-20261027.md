# C2C 运营体验验收 · 2026-10-27

本轮核对 C2cAdminController、C2cAdminViews、C2cAdminReview 与 C2cViews 的实际字段及权限规则后完善操作界面。

- 商家、收款账户、广告与申诉按业务使用统一表格、中文状态、筛选与 30 条分页，保留原始状态用于决定。缺分页、重复身份、错偏移、非法版本或未知状态不能显示成成功的空表。完整标识、币种与金额在详情中可读，长整数不经过浮点转换。
- 切业务区、分页、状态及管理员会清除旧列表/详情，取消读取。选择新记录立即清空原因、实名确认及私密资料；旧详情返回时核对请求与选中对象，不能串到另一个账户。
- 查阅实名资料沿用审计入口，核对 accountId、用户、版本、方式及币种。有效 KYC 与人工核对勾选后才允许通过；本人商家与收款账户不能由本人审核。广告按当前状态提供暂停或恢复，已处理申诉仅可查看。
- 申诉先读取绑定原订单，显示原买方、卖方、资产、法币、数量和条款；参与该交易的管理员不能裁决。确认包含原申诉、原订单、双方、金额与原因；不允许在界面修改资金收款人或原金额。
- 延续 C2C_APPROVAL_REQUIRED 的原协议：服务端要求双人审批时，以同一正文、方法、路径、服务与 SHA-256 办理审批后发送，精确审批 ID 保留字符串。初次权限拒绝不作为业务已执行；裁决结果仍显示原订单的资金处理中状态。
- 写入即时加锁并锁定导航和工作区；失败后清除未确认的目标，要求刷新原记录，重填原因。初始读取、错误、空页及提交提示分别呈现。
- 配置、质押规则、资金核对各自校验；未知配置不显示为已关闭，缺失规则不显示未配置或零金额。报告未就绪时仍能停止新交易，开放需要 MATCHED。报告每 2 秒、最多 30 次重读，跳过已有读取与提交，不重建配置表单；切页释放计时器和连接。
- 初始化不发送金额正文；经营开关、规则、市场和方式更新前显示目标与原因。金额/价格继续按十进制字符串提交，费率、法币小数位和付款窗口使用后端限定的整数范围。窄屏使用记录卡片，详情滚动预留固定顶栏空间。

浏览器脚本有 6 组场景，实际点击商家审核、长 ID 分页、自审禁用、实名详情的迟到与错目标、人工确认、广告暂停失败恢复、原订单独立性、申诉双人审批/正文摘要/精确 ID、已处理状态、配置未就绪、停开限制、规则与收款方式更新、新增市场、无正文初始化、账户切换，以及 1440×1000、390×844、320×844 深浅主题与 60 秒观察。最终命令、截图及采样见 [机器记录](c2c-experience-20261027.json)。

未测范围：全部数据及审批为隔离接口数据，没有真实商家审核、账户初始化、授权、资金裁决或转账。未重新验证真实数据库事务/锁、双方实时协作、审批实际消费、全部商家状态与市场修改、C2C 会话/私密附件及长时间断网恢复。没有修改 Java、SQL、Core 或原生 Client。本机 DOM、监听器、堆和任务时间只用于短时稳定性观察，不代表生产性能、永久无泄漏或真实财务验收；全站目标保持继续。
