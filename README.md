# Surprising Admin Web

React / TypeScript 管理后台。开发运行 `npm run dev`；提交前执行 `npm run lint` 和 `npm run build`。

## C2C 运营体验（2026-10-27）

商家、收款账户、广告和申诉使用统一表格、状态筛选、每页 30 条分页及窄屏记录卡片。加载、错误与真实空页独立展示，返回对象、版本或分页不匹配时停止载入。详情显示完整标识、金额、币种和处理原因；提交中锁定当前对象，失败后重新读取原记录。

实名资料查阅与具体账户、用户及版本绑定，迟到响应不能覆盖新选择；有效认证和人工实名核对完成后才能通过。申诉先读取原订单双方与原金额，交易参与人不能裁决；完整目标确认后沿用原双人审批与正文摘要绑定。已裁决记录仅供查看，资金处理中的订单不会显示为已完成。

经营配置、质押规则和资金核对分别校验。未知规则不显示为零金额或未配置；资金核对未就绪时可停止新交易，开放新交易需要核对一致。未就绪报告有界重读，后台读取不再清除配置草稿；初始化、规则、市场和收款方式变更均有目标确认。

复现与限制见 [C2C 运营验收](docs/validation/c2c-experience-20261027.md)。本轮没有对真实商家、收款账户、资金或申诉作出操作。

## 权限治理与审批体验（2026-10-27）

角色权限支持搜索勾选和完整代码编辑，保存前显示新增、移除及替换目标；保留目录未列出的已有代码，SUPER_ADMIN 只读。切换角色取消旧请求并清除旧授权，错误响应不能附到另一个角色。提交期间锁定工作区，失败后重新读取核对；保存继续沿用原敏感操作审批和正文摘要绑定。

审批详情用中文标签完整展示申请人、路径、查询参数、正文 SHA-256 和有效期；填写意见并确认目标后才能批准或驳回。本人申请、已处理及过期申请仅可查看；打开的申请到期会自动停止允许决定。筛选变更清除旧详情并提示重新查询，提交失败清除旧结果。批准只记录决定，实际业务仍由原请求人执行。窄屏定位详情保留固定顶栏下的留白，长编号与摘要可换行。

复现与边界见 [安全治理体验验收](docs/validation/security-experience-20261027.md)。本轮浏览器使用隔离接口数据，未修改真实角色或审批。

## 交易维护

侧栏「交易维护」按当前产品线连接真实后端
`/api/v1/admin/trading/orders/maintenance?productLine=...`，沿用现有登录、权限、审批和审计。

1. 选择产品线，从下拉框选择真实币对（包含暂停等状态，自动读取全部分页），再选择用户范围和操作方式，填写原因并预览 Core 当前订单/持仓。
   下拉框支持输入关键词实时模糊过滤（忽略大小写），点击或方向键/回车选择；不接受未选中的自由文本。
   切换产品线会清除旧币对；列表加载失败可重试，草稿中的币对须在当前列表中才能提交。
2. 可选撤单、市价 IOC 平仓、指定价格的限价 IOC 平仓、固定价格整币对清退。现货只能撤单；
   期权固定清退填写标的结算价格。所有价格为整数 ticks，ID 和数量保留字符串精度。
3. 输入准确币对二次确认，再通过现有审批流程。请求草稿及 UUID 按管理员保存到 localStorage，
   离开页面办理审批后返回仍保持相同审批参数；修改内容会更新请求身份并要求重新预览。
4. 查看任务步骤、实际错误、命令记录和当前残留。列表每 5 秒刷新；预览有分页边界，不能把当前页条数当作总量。
5. 流动性不足时剩余仓位不会消失，可补充对手盘后审批重试，或明确解除维护。
   未知命令结果必须先核对；固定清退已开始后不能改价或恢复交易。保险不足需补足后重试。

维护限制覆盖整个币对，即使只处理一个用户。撤单/撮合平仓完成仍保留限制，必须另行恢复交易。
固定清退完成后 Core 永久停止该币对交易；产品展示下架仍使用原有市场配置。
订单处理范围是普通单和触发单，算法任务不在此页面删除，子单受 Core 门控约束。

部署前需先应用后端 `migrations/20260906_trading_maintenance.sql` 并部署匹配的 Core/Provider。
本次 Core 快照格式变化，已有数据迁移边界见后端根 README。

验证包括 TypeScript 检查、生产构建，以及真实浏览器上的预览、确认、审批请求头、草稿恢复、长整数显示、
现货/期权选项和窄屏交互。浏览器测试使用接口契约桩，实际财务行为由后端真实 PostgreSQL + Core 集成测试验证，
不能将两者合称为已通过生产网络全栈验收。

## 产品线接入

“产品市场”页面的“产品线接入”区域通过 `/api/v1/admin/product-lines` 读取六产品设置和本机连接状态。

## 代码结构与请求边界

`App.tsx` 只负责登录、导航、权限和审批对话框；`pages/` 按运营业务拆分并按路由懒加载。
`components/` 复用表格、分页及页面恢复边界，`features/` 放用户详情与合约表单字段，`api/` 负责接口，`lib/` 放产品映射与输入校验。

金额最小单位、订单数量和 int64 ID 通过十进制字符串传输，提交前验证格式与范围；审批哈希绑定最终发送的同一份 JSON 原文。
网络截止时间覆盖响应头与完整响应体：JSON 默认 15 秒/8 MiB，文件默认 120 秒/64 MiB。超时会取消请求，写操作不自动重发，须先查询原操作结果。
刷新凭证明确收到 401/403 才退出登录；临时服务或网络故障保留会话并显示错误。损坏或过期的本地会话回到登录入口，存储被禁用时只在当前标签页保存会话。

登录响应的用户名、邮箱可为空，显示名称沿用用户名、邮箱、用户 ID 的顺序；会话有效性仍校验 ID、角色、状态、令牌与有效期。

费率配置提供已有的用户费率计划新增、更新、禁用及「用户当前有效费率」查询。查询有效费率须同时输入用户 ID 与合约永久 ID，并选择产品线。
档位代码仅作为计划标签。已移除服务端从未支持的 VIP 阈值配置与自动刷新按钮，避免页面持续请求不存在的接口。

## 账户资产查询与资金操作反馈

账户查询先输入用户 ID，并显式选择产品账户；基础余额、流水、产品余额、持仓及调整追溯均携带当前产品线。
选择 FUNDING 时显示独立的产品线选项，产品余额/持仓/产品流水/划转区提示选择产品账户，避免回退到默认产品。

人工调整保留整数最小单位、目标用户/产品确认及原有审批绑定；提交或等待审批期间锁定表单，切换目标清除调整草稿。

`scripts/account-experience-qa.mjs` 在 `http://127.0.0.1:5184` 验证桌面/窄屏、深浅主题、慢响应隔离与审批失败反馈。
使用 `QA_PLAYWRIGHT_MODULE`、`QA_CHROMIUM`、`QA_OUTPUT` 指定浏览器和证据目录。
全部 API 均为隔离契约夹具，写操作固定返回失败，不执行真实人工调整或生成快照。
详见 [账户资产验收记录](docs/validation/account-experience-20261026.md)。

## 平台提现申请与托管运营

钱包运营页新增独立的平台提现申请区，读取现有 `/api/v1/admin/wallet/withdrawals`。
该申请从 SPOT 资金账户出款，按平台 UUID 追踪审批、扣款、托管提交和退款；与托管钱包自身的单据/审核分开显示。
可按平台状态读取 50/100/200 条，在已加载申请中按用户、编号、地址、币种或网络搜索；达到读取上限会明确提示。
详情保留完整地址、精确金额与最小单位，客户请求编号便于核对用户提供的原编号，其他处理与审计字段可展开查看。

只有 PENDING_APPROVAL 显示通过/拒绝；DEBIT_UNKNOWN、BROADCAST_UNKNOWN、REFUND_PENDING 显示重试原申请。
操作原因、完整目标确认及原有敏感操作审批均保留。提交中锁定目标，网络或响应异常后必须刷新核对，再决定是否继续。
已知响应会刷新原状态列表，不将审批通过或托管提交当作链上完成。
托管运营服务未连接时不显示假零值，平台申请区仍可独立查询；原托管读取支持取消，防止旧请求覆盖刷新。

验证入口为 `scripts/custody-withdrawal-qa.mjs`，使用 `QA_PLAYWRIGHT_MODULE`、`QA_CHROMIUM`、`QA_OUTPUT`，
开发页为 `http://127.0.0.1:5184`。脚本全部拦截 HTTP，不执行真实审批或资金动作。
详见 [平台提现验收记录](docs/validation/custody-withdrawal-20261026.md)。

## 合规审核体验（2026-10-26）

合规页独立呈现用户、风险标签、AML 与验证器申诉的读取结果，故障不显示假零统计。
